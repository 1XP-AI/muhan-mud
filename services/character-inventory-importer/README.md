# Character inventory importer

This is a deliberately narrow, one-shot administrative backfill tool for the
ownership index `public.game_characters`. It reads only JSONL generated by
`scripts/export-player-inventory.py`; it never opens player files and it never
accepts raw player bytes, passwords, JWTs, or service-role keys.

The preferred Kubernetes job path mounts the legacy PVC read-only and scans it
in place. The scanner requires an absolute `--mud-home`, never follows a root,
shard, or player-file symlink, uses no-follow/nonblocking regular-file opens,
and streams a bounded SHA-256. It only retains the metadata needed for the
insert and only prints aggregate outcomes:

```sh
cd services/character-inventory-importer
DATABASE_URL='postgresql://inventory_admin:...@db.internal:5432/postgres' \
  npm run start -- --mud-home /mnt/muhan --world-id muhan
```

The scanner rejects unexpected/nonregular/unreadable entries, malformed paths,
invalid canonical names/shards, duplicate identities, and files over 64 MiB.
It caps a run at 100,000 candidate entries. The PVC must be mounted read-only.

The reviewed JSONL operator mode remains available when scanning a PVC is not
appropriate. Generate the inventory on the isolated legacy host and transfer
the metadata-only JSONL through the approved operator channel:

```sh
MUHAN_HOME=/legacy/muhan python3 scripts/export-player-inventory.py --strict --output /secure/player-inventory.jsonl
```

On the database-admin host, use a **direct PostgreSQL administrator** URL in
`DATABASE_URL`. Do not use a Supabase REST URL, JWT, anon/authenticated or
`service_role` credential. The executable does not read Supabase URL/key
variables. Run a dry-run first (the default):

```sh
DATABASE_URL='postgresql://inventory_admin:...@db.internal:5432/postgres' \
  npm run start -- --inventory /secure/player-inventory.jsonl --world-id muhan
```

After an independent review of the aggregate dry-run result, repeat with
`--apply`. There is no implicit apply mode.

```sh
DATABASE_URL='postgresql://inventory_admin:...@db.internal:5432/postgres' \
  npm run start -- --inventory /secure/player-inventory.jsonl --world-id muhan --apply
```

## Contract

- Only exact exporter records with `status=ok` are candidates. The importer
  rechecks canonical C-style name, SHA-1 shard, relative path, lowercase
  SHA-256, size bound, and absence of duplicate canonical identities.
- For each `(world_id, legacy_name_key)`, a serializable transaction takes a
  transaction-scoped advisory lock then a row lock. An absent row is inserted
  as `imported_unclaimed`, owner `NULL`, `storage_format=1`, with the exact
  canonical name/shard/hash.
- A byte-equivalent existing unclaimed import is idempotent. Any owner,
  lifecycle, hash, or identity mismatch is quarantined. The tool never updates
  or deletes rows, including quarantined rows.
- Standard output contains aggregate counts only. It never emits player names,
  paths, hashes, inventory content, passwords, or credentials. A quarantine
  produces a nonzero exit code so operators must resolve it before proceeding.
- The JSONL mode similarly accepts only a regular, no-follow input file no
  larger than 64 MiB and no more than 100,000 nonblank records.

## Review-manifest validation

`src/imported-unclaimed-manifest.ts` is a pure, DB-free boundary for the
committed `muhan.imported_unclaimed_manifest` v1 output from
`scripts/build-imported-unclaimed-manifest.py`. It admits only a dry-run
manifest with an empty `rejections` list, exact closed top-level/candidate
fields with no duplicate decoded JSON member names, canonical sorted
identities, and re-derived shard/digest/size values.
It rejects raw manifests over 64 MiB before copying, UTF-8 decoding, or JSON
parsing, matching the importer's existing bounded-input policy.
On success it returns only the closed candidate metadata and the SHA-256 of the
exact raw manifest bytes; every failure exposes only the generic
`invalid_imported_unclaimed_manifest` error code.

`src/imported-unclaimed-checkpoint.ts` is a separate pure, non-authoritative
resume boundary: it orders the parsed candidates by canonical identity and
binds a local cursor to that exact manifest SHA-256. It performs no database or
file writes; a changed manifest, an unknown cursor, or ambiguous identity is
rejected before any caller can resume.

Run `npm test`, `npm run typecheck`, and `npm run build` before an operator run.
