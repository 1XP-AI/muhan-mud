# 터미널 전용 웹 UI 및 원작 가입 흐름

상태: 2026-09-08 사용자 요구 반영, 구현/배포 전. Go 실행 계획의 G2 인수 기준이다.

현재 구현 업데이트: 루트 페이지를 `ClassicTerminal`로 교체했고 별도 웹 로그인
대신 런타임 `MUD_GO_GATEWAY_URL`로 Go line 프로토콜에 연결한다. 기존 인증
컴포넌트/테스트는 비교 자산으로 보존하지만 새 루트 진입에서는 사용하지 않는다.
회색 바탕·남색 중앙 xterm, 기본 focus/창 복귀/선택 보존, 한글 코드포인트 삭제,
암호 echo 금지와 응답 대기 중 입력 차단, 모바일 IME 조합·viewport·재접속 focus
경계가 구현되어 있다. 웹 전체 library 테스트 51개와 TypeScript 검사가 통과했다.
실제 브라우저 스크린샷·Go 연결 E2E·IME·모바일 키보드·긴 줄 wrap 검증은 남아 있다.
아래 인수 체크리스트 전체를 통과한 것으로 읽지 않는다. 배포하지 않았다.

## 화면 방향

대상은 브라우저에서 원작 무한대전을 플레이하는 사람이다. 페이지의 유일한 역할은 게임 터미널을 제공하는 것이다. 새롬 데이터맨의 PC통신 감성을 참고하되 특정 버전의 픽셀 복제를 약속하지 않는다.

- 가운데 xterm 한 개만 배치한다. 별도 로그인 카드, 가입 폼, 캐릭터 연결 페이지, 대시보드, 진행 단계 카드, 사이드바는 없다.
- 디자인 초안: 바깥 회색 `#C0C0C0`, 얇은 테두리 `#808080`, 터미널 남색 `#000080`, 기본 글자 `#E0E0E0`, 강조 흰색 `#FFFFFF`, 선택 강조 청록 `#00FFFF`. 게임 ANSI 색상과 가독성을 함께 확인한다.
- 글꼴: 터미널/프롬프트는 D2Coding 계열 한글 고정폭과 monospace fallback, 필요한 접근성 안내는 시스템 sans-serif. 폰트 사용 조건과 한글 폭을 구현 전에 확인한다. 외부 장식 제목을 만들기 위해 글꼴을 추가하지 않는다.
- 특징은 얇은 고전 창 테두리 안의 남색 터미널이다. CRT 노이즈, 스캔라인, 불필요한 애니메이션은 넣지 않는다.
- 데스크톱은 중앙 정렬, 모바일은 여백을 최소화해 가용 화면을 채운다. 고정 80열을 무조건 강제하지 않고 원작 ASCII 정렬과 작은 화면 가독성을 함께 검증한다.
- 연결 중·끊김·재접속 안내도 터미널 안에 표시한다. 비밀번호와 입력 중인 명령을 재연결 시 자동 재전송하지 않는다.

디자인 자체 점검: 기존 카드형 랜딩/인증 화면은 이 요구와 맞지 않으므로 제외한다. 장식보다 한글 가독성과 입력 가능 영역을 우선한다. 구현 뒤 실제 화면 크기별 스크린샷으로 확인한다.

## 가입과 로그인

URL 접속 → 터미널 연결 → 원작 이름/신규 생성 안내 → 터미널 내 비밀번호 및 원작 캐릭터 생성 절차 → 게임 시작.

기존 캐릭터는 이름/비밀번호로 접속한다. 신규 이름 검사·중복 생성 경쟁·생성 중 취소/연결 끊김·재시도를 서버 상태 머신으로 처리하고 불완전한 계정이나 캐릭터를 남기지 않는다. 원작 질문과 입력 순서는 G0에서 C 동작을 조사해 확정한다.

별도 웹 계정, 이메일 가입, OAuth, 관리자 캐릭터 연결을 정상 플레이의 선행 조건으로 요구하지 않는다. Supabase PostgreSQL에 게임 identity와 캐릭터 데이터를 저장한다. Supabase Auth 재사용 여부는 내부 구현 선택일 뿐 사용자에게 또 다른 가입 절차를 추가하지 않는다.

가입 전 WSS 세션은 가입/로그인 명령만 처리하며 월드에 진입할 수 없다. 비밀번호는 화면·스크롤백·일반 로그에 노출하지 않고 평문 저장하지 않는다. 기존 비밀번호 저장 형식과 이관 방법은 별도 계약 테스트로 확인한다. 기존 웹 계정/연결 데이터는 자동 삭제하지 않으며 충돌 시 이관 규칙으로 해결한다.

## 포커스와 입력 계약

- 터미널 준비 완료 시 기본 포커스를 부여한다. 초기 모바일 화면에서 키보드 강제 표시를 보장하지 않으며, 첫 터미널 탭으로 입력할 수 있게 한다.
- 창/탭으로 돌아오거나 터미널 빈 영역을 누르면 입력 포커스를 복원한다. 준비 전 이벤트와 컴포넌트 제거 이후 콜백을 안전하게 처리한다.
- 타이머로 반복 focus하거나 모든 blur/keydown에서 포커스를 빼앗지 않는다. 텍스트 선택/복사, 스크롤백 읽기, 브라우저 단축키, 보조기기 이동을 존중한다. Tab으로 터미널 밖으로 이동할 수 있어야 한다.
- 한글 IME 조합 중 focus/resize 재설정, Enter 중복 전송, 조합 중 Backspace 유실이 없어야 한다. 입력마다 터미널을 재생성하지 않는다.
- 모바일 키보드가 열려도 현재 프롬프트와 입력 줄이 가려지지 않아야 한다. 화면 회전·키보드 닫기/재열기 시 글자 크기와 행/열을 맞추고 연결을 유지한다.
- 스크롤백을 읽는 중 새 출력이 와도 강제 하단 이동하지 않는다. 명령 입력 후에는 현재 입력 위치를 볼 수 있게 한다.

## TDD/인수 체크리스트

아래 항목은 모두 미실행이다. 테스트 작성→실패 확인→구현→통과 순서로 진행한다.

1. 웹 가입 페이지를 거치지 않고 첫 접속에서 이름/가입 프롬프트를 받는다.
2. 신규 캐릭터 생성→플레이→종료→같은 이름/비밀번호로 재접속해 상태를 복원한다.
3. 기존 캐릭터 로그인, 잘못된 비밀번호, 이름 충돌, 중복 생성, 생성 도중 끊김을 검증한다.
4. 가입 전 게임 명령이 적용되지 않으며 비밀번호가 화면/스크롤백/수집 로그에 남지 않는다.
5. 초기 focus, 창 복귀, 클릭 복원, 선택/복사 보존, Tab 이동, 스크롤백 유지가 기대대로 동작한다.
6. 실제 한글 IME로 이름/명령을 입력하고 Enter/Backspace 중복·유실을 확인한다. 자동 테스트만으로 IME를 검증 완료했다고 하지 않는다.
7. 데스크톱 및 모바일 크기의 자동 브라우저 테스트를 수행하고, iOS Safari/Android의 실제 키보드는 별도 확인한다. 기기 접근이 없으면 미검증으로 남긴다.
8. Go 서버와 실제 PG를 사용한 브라우저 E2E에서 C 프로세스 없이 위 흐름을 통과한다.

구현 배정: 비용 정책에 따라 세션/인증 상태 머신, IME·포커스 통합, 스타일·화면 크기별 회귀 테스트 모두 Luna max만 사용한다. 다른 모델로 자동 승격하지 않는다. 기존 웹 테스트 중 웹 로그인 필수 가정을 수정하고, 사용자 테스트용 접근 경로는 배포 승인 이후 제공한다.
